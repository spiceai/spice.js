# spice.js v3.3.1

## Fixes

- **Faster large Arrow Flight results on Node.js.** The Flight client now opens each channel with a 16 MiB HTTP/2 flow-control window. Before, `@grpc/grpc-js` used HTTP/2's default 64 KiB window and never grew it, so throughput was capped at about window / round-trip time. A 1.5M-row (86.6 MiB) query from Spice Cloud took 212–272 s with v3.3.0 and 2.2–2.5 s with spicepy. Two new optional `SpiceClientConfig` fields (Node.js only) change the defaults: `flightFlowControlWindow` (bytes, an integer from 65535 to 2147483647; an invalid value throws from the constructor) and `flightChannelOptions` (other `@grpc/grpc-js` channel options, applied last). ([#373](https://github.com/spiceai/spice.js/pull/373))

  ```ts
  const client = new SpiceClient({
    apiKey,
    flightFlowControlWindow: 32 * 1024 * 1024,
    flightChannelOptions: { 'grpc.keepalive_time_ms': 30000 },
  });
  ```

- **Flight accepts messages up to 100 MiB.** The Node.js Flight client now sets `grpc.max_receive_message_length` to 100 MiB, the same limit the runtime applies. Before, it used grpc-js's 4 MiB default, and a query that returned a large record batch (for example, wide rows with nested or long string columns) failed with `RESOURCE_EXHAUSTED: Received message larger than max`. The browser build uses HTTP and does not change. ([#367](https://github.com/spiceai/spice.js/pull/367))
- **TLS options apply to HTTP calls.** `tlsRootCertFile`, `tlsClientCertFile` and `tlsClientKeyFile` now apply to HTTP calls as well as Arrow Flight. Before, against a runtime with a private-CA certificate, `isSpiceReady()` and `isSpiceHealthy()` returned `false`, and `refreshDataset()`, `runtimeStatus()`, `search()`, `nsql()` and the `/v1/sql` fallback failed with `UNABLE_TO_VERIFY_LEAF_SIGNATURE`. The mTLS client certificate was never sent over HTTP. ([#361](https://github.com/spiceai/spice.js/pull/361))
- **`search()` rejects a malformed `/v1/search` response.** A 200 response without `results`, `duration_ms`, or a match's `dataset` and `_score` (for example, a proxy's error envelope) now throws an error that names the missing field. Before, it failed with a `TypeError` or resolved with `undefined` fields. The `score` field that older runtimes send is accepted as an alias. ([659ba83](https://github.com/spiceai/spice.js/commit/659ba83ef355ad3bf77858bb51ae3ead9a84b4a7))

## Security

- **Dependency minimums raised for security advisories.** `undici` is now `^7.30.2` (was `^7.30.0`) and `@grpc/grpc-js` is now `^1.14.7` (was `^1.14.3`), so no install, including one with an existing lockfile, resolves a version with these advisories. ([#374](https://github.com/spiceai/spice.js/pull/374))
  - `undici` < 7.30.1: GHSA-2m5v-pch6-74hx (`Agent` drops TLS options, which can bypass certificate validation), GHSA-4w7w-5xrc-9h26 (cache poisoning through cross-origin redirects), GHSA-f72v-6w45-q472 (Subresource Integrity bypass), and denial-of-service advisories GHSA-4qv8-2p9j-2685, GHSA-xjj6-f33q-929c, GHSA-qrxm-fqhp-jwvm, GHSA-9fm3-97px-rjf6 and GHSA-55wc-3pg8-jfw6.
  - `@grpc/grpc-js` < 1.14.5: GHSA-m9gg-hp2v-232j (`getAuthContext` can report unauthorized certificates as authorized) and GHSA-f596-whhp-79r4 (server handler error messages sent to the client).
